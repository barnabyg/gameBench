# Domain docs

Use one glossary and one architecture decision record (ADR) directory for this repository.

- Before exploring, read the root `GLOSSARY.md` and any records in `docs/adr/` relevant to the task. Proceed silently when these files are absent.
- Use glossary terms in issues, code, and tests. Bring unresolved terminology to the domain-modeling skill. Record terms and decisions as they are settled.
- If a proposal conflicts with an ADR, cite the record and explain why the decision merits revisiting.
